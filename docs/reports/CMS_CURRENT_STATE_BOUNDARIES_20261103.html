结论：新的离线合同已通过 18 组列明验证，覆盖普通采购计划、开 PO、新增供应商、合并 PO、保存中断和跨月。上轮“漏掉保存中”和“新增 50 箱仍显示 200 箱”的候选缺陷已在这些场景中解决。尚未修改生产程序，不代表整个 CMS 已完成优化。

这次怎样减少不必要的机制

先测试了逐条给任务留下保存标记的方式，但合并 PO 在第一条标记后中断，会留下不完整的保护范围。这个失败实验保留在 f15f86e，不作为部署候选。

最终实验沿用现有的一条原请求准备记录 PREPARED，在它首次保存时一并附上受影响根任务列表。这样同一张合并 PO 的所有任务，在同一次记录写入中被声明。没有另建业务日志、待办队列、库存账或新集合。

  1. 既有原请求准备记录与受影响任务列表一起保存；业务字段尚未写入。
  2. 沿用原程序保存价格、计划、份额或 PO。没有重算另一套业务数量。
  3. 读取只取该任务当前结果，并查与它有关的尚未完成请求。发现待完成请求时，按确定 ID 读取有限条原业务证据。
  4. 证据未齐：展示前一个已确认值并标明待恢复；证据齐全：即使当前结果写回尚未完成，也能确认新结果。
  5. 写入流程更新所有受影响任务的固定当前记录，随后把原 PREPARED 上的待完成任务列表清空，最后沿用原 RESULT 回执。历史记录和原请求身份保留。

读取本身没有补写、初始化、静默修复或退回全历史。期间若另一个保存改变了读取依据，明确要求重读，避免混用前后版本。已有业务计算与单事件解析函数仍是结果来源；实验只在核对真实前一版本后，以本地副本解析最新事件，没有改写历史事件。

程序突然结束的边界

另有三组模型测试：准备记录、任务字段、最后业务事件写完时，模拟清理不能运行，再把已持久化数据载入新执行环境。待恢复/已确认状态仍正确，原锁仍保留。原程序的 PLAN 锁在这种情况下仍阻止继续保存；本轮没有新增超时删锁、抢锁或自动接管。此项验证的是安全状态保留，不是宣称自动恢复能力已完成。

另一个既有边界已在未修改的原程序与候选中同时复现：旧请求已完成业务事实但缺少 RESULT，随后另一次保存改了价格，再重试旧请求，会被原有版本保护拒绝。最新价格保留，不会回滚；本轮没有把它冒充为已修复的自动恢复。

还验证了确实有一个未完成请求的正例：三种历史规模均为 6 次按 ID 读取、2 次待完成查询（同一条请求前后各返回一次），结果一致，读取没有写入。不是通过永远返回空查询来制造提效结果。

待完成查询在本实验中使用内存索引适配器；它不是已上线的 Wix 查询实现。官方文档确认支持标量数组索引和 hasSome，但仍须核对本站可用索引、字段结构及实际查询。没有测量线上延迟、物理扫描量或百万行容量；正常完整工作台和原保存准备也尚未脱离历史。

固定记录与增长代价

实验在已有 NCT/GHR Activity 内，每个根任务保留一条固定当前记录，来源成员随同保存；不把当前记录塞进可能被整条更新的 Tasks。每次保存覆盖同一条，不按每次点击新增当前记录。尚未选择正式字段名或写入生产。

因此，这条路线主要解决日常读取工作量；它不是减少历史容量的最终方案。不能以节省读取为由隐瞒额外写入，也不能删掉仍负责保存恢复的历史。后续减少冗余事件和归档容量需要独立证据。

最小字段及索引候选

  • 现有 PREPARED 增加实验 readStateSchema 与 pendingReadRoots：列表非空表示仍需核对当前投射，全部写回后清空。不再同时保存重复的 pending 布尔值。
  • 固定当前记录含公司、根任务、成员已确认结果、份额、原请求标识及一致性校验。只作内部采购读取结果，不包含独立付款或库存余额账。
  • 候选查询为对 pendingReadRoots 做成员匹配并限制返回条数；该数组需要合适索引。出现多个未解决冲突时报告，不默默截断。

参考：Wix 官方索引说明明确列出 hasSome 及标量数组支持，并说明索引有额外存储和写入成本。CMS 索引配置说明说明配额取决于套餐。这里没有假定本站已经存在该索引，也没有创建索引。

上线前还缺什么

  1. 覆盖会影响同一状态的其他现有入口，包括旧编辑、成本补抓、特殊采购、新订单接收等。不能只上 PLAN/PO/ADD_SOURCE，然后让其他入口产生旧状态。
  2. 核对正式 Wix 原件与对应消费者，验证真实索引、请求数量和页面表现；保持权限、财务锁定、库存、Loaded 和客户接口原样。
  3. 准备现有记录的只读初始化预览：缺失、未完成或矛盾的项目不能自动确认为正常。具体存储写入与启用范围需另行批准。
  4. 固定当前记录的读取只是采购计划的一部分；完整任务发现、库存来源、借还、Loaded、隔离和财务各有权威依赖，不能以本报告声称全站不再读取历史。

下一步应把其余采购写入入口和正式索引证据补齐，形成可审查的精确生产补丁与初始化清单。旧锁自动接管属于另一项行为改变，不擅自混入这次读取优化。
