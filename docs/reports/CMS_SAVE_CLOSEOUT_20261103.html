1. 相同内容不再生成采购修订

旧逻辑即使采购数量、成本和运输都没有改变，只要使用新的保存请求，仍会生成准备记录、价格记录、来源分配记录、采购计划记录和结果回执，共5条。新逻辑复用既有比较方法，只有真正改变的字段才进入修改清单；没有变化时使用原有提示退出。

这是针对已复现路径的减少，不能解释为每次正常保存都省5条。临时并发锁仍会建立和释放，故“没有新增持久记录”不等于“完全没有数据库操作”。页面读取全历史的问题也没有因此解决。

数量、FOC组成、折扣、运输、草稿供应商、计价依据真正改变正常保存，不能仅因最终单价相同而吞掉修改

4. 第二项必须满足的返回规则

  1. 用现有准备记录和确定的业务事件身份辨认未完成保存，不能仅看是否存在RESULT。
  2. 受影响的采购来源、同一客户的来源合计及其PO不得显示混合金额或假0；明确显示“保存待恢复”。
  3. 已确认的Loaded、付款和SI历史保留；无关任务继续读取和工作。
  4. 原请求继续恢复，不新建回执体系、不放松财务锁、不改变库存权威。
  5. 完整业务事件、关联身份和任务版本都能证实时才解除待恢复；时间过去不等于保存成功。
  6. 修改前分别验证首次计划、已开PO、同产品多来源、借货、部分SI及结果回执单独丢失。不能以一个成本例子通过就覆盖全部消费者。

这部分尚未改生产代码。共享读取同时服务Purchase、Finance、Warehouse、Support；直接把整个投射改成报错会扩大故障，直接重排数据库写入只会把不一致窗口换位置。所以上述返回约定必须先通过隔离候选验证，再做最小同步。
