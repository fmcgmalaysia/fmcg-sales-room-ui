### 三个弹窗候选

1. **Transaction Details**：Invoice身份、币种、开票与真实发货日期；货物行的品名/包装/箱数/单价/行金额；费用行的收费内容/说明/必要的数量单价/金额；合计、相关Invoice及客户文件。历史值来自开票确认记录。
2. **Payment Details**：原Invoice金额；每次分配到本单的实际付款、日期、证明入口；存在时显示CN/DN/退款/撤销；Total Paid及Amount Due。合并付款须说明原总收款与本单分配额，避免把一笔钱复制为多笔。
3. **Documents**：文件类型、编号、日期、打开按钮。仅文件较多时需要；普通文件直接打开。草稿、作废和内部资料不得混入有效下载按钮。

顶部优先展示当前Outstanding；存在未分配款才补充Available Credit和净余额。日期筛选明确Invoice Date或Payment Date；查询旧月份不改变当前总欠款。三个月完整查询、月份筛选及大历史分页尚未验收。

## 4. 修改前必须核实的财务边界

这些是建议与验收要求，不是当前实现能力声明。

- 复用现有Finance唯一客户账写入路径；确认现有数据是否有Invoice核销关系。不能从客户最近付款推测逐单Last Payment或欠款。
- 一笔收款可分配多单，一单可收多次；累计核销不超过有效可用款。并发确认、重复请求、超时后原请求恢复须覆盖。
- 未分配预付款、超额款及历史无归属收款保留客户余额；不得猜配、丢弃或造负数Invoice。Finance可确认分配，不自动跨客户/公司/币种抵扣。
- CN/DN/退款及撤销只有一种有效记账方式。特别防止同一额外费用既开Invoice又通过DN重复加应收；同一贷项也不能减两次。
- 费用Invoice建议Support制作/上传，Finance确认后正式计入应收并对客户显示。这是待确认的新增权限边界；不得偷偷改变现有货物SI开票权限。
- Support上传金额仅参考；Finance独立确认真实收款/CN/DN。新金额输入0.00、编辑后两位小数，底层成本精度与未知值不被改成0。
- Invoice金额、商品、箱数、物流使用确认快照；付款分配、更正及文件版本保留事实，不覆盖已正式记录。不得把开票日期或Loaded日期当真实Shipment Date。
- 旧数据迁移/补齐不得根据模糊编号猜配。先量测范围、列出待核销条目，再沿用批准流程处理；不能另开一套手工余额逻辑。
- 文件按交易/客户授权投射；复用同一原PDF，不让供应商单据或包含其他客户信息的内部材料进入客户共享目录。
- 查询、筛选、下载不增加业务历史；分页读取，余额与列表共用权威财务记录。读取优化须保留一致性保护，不能为了速度省掉权限和版本校验。

## 5. 最终验收表应包含的场景

| 场景 | 预期结果 |
| --- | --- |
| 一单分两次付款 | 两笔独立明细，Last Payment为最后有效一笔，余额正确 |
| 一笔50000分货物48000和费用2000 | 总账仅一笔50000，各单只减自己的分配额，同一证明复用 |
| 先收订金后开Invoice | 未开票时可查付款；核销后逐单和总账均能对上 |
| 超额付款/历史未分配收款 | 余额保留为Credit或待核销，不伪造逐单付款 |
| CN、DN、退款、撤销 | 总账与逐单可解释，历史保留，不双重记账 |
| 费用Invoice含运费和保险 | 无库存/Loaded变化，确认后形成一次应收，Buyer/Sales同金额及文件 |
| 重复提交、两人并发、响应丢失 | 无超额核销/重复入账，原请求可恢复，冲突明确 |
| NCT/GHR、不同客户、不同币种 | 不串账、不跨币种直接相减；隐藏公司筛选不放松权限 |
| 查三个月前Invoice及上月付款 | 按正确日期查询，分页完整，当前欠款不随筛选改变 |
| 旧Invoice开出后Desk变化 | 历史箱数/金额不漂移，剩余订单继续保留 |
| 普通客户及转发文件 | 客户只能列出自己的记录；允许的单文件可下载转发，目录仍私有 |
| Buyer/Sales/Finance同一单 | Invoice金额、已收、调整、欠款和文件一致；Sales没有上传/入账权限 |
