# Supplier Account closure

User authorized starting the identified closeout work and explicitly confirmed supplier closure must not wait for customer sales invoices. This patch implements the supplier-account closure boundary only. Department-wide issue routing, transaction-history direction/proof improvements, automatic payment summaries and real cross-department acceptance remain separate unfinished follow-ups.

Framework: root AGENTS/START_HERE, current spacing and payment-scope release records, MASTER standard, settlement/journal, shared PO projection, credit operations and Account readers/writers reviewed. Recovery runtime27f0984 / documentation27d3753; prior exact Wix sources and release receipts preserved privately. Existing annotated verified/purchase-row-drag-save-20261016 remains a limited Purchase invariant, not a broad Finance acceptance claim. Fresh full Wix Account, accountSettlement, purchaseOrderWorkflow and supplierCredit sources matched repository exactly after CRLF normalization before edits.

Single objective: make supplier completion an explicit, audited Finance action without prematurely archiving unfinished customer sales work. New finance.closure uses the existing PurchaseOrders details and operation journal; no new endpoint, collection or authorization. Whole-order HISTORY and customer-invoice gates remain unchanged. Supplier Accounts Open/Closed now uses supplier closure, with legacy HISTORY fallback. Existing legacy archived records are not migrated.

Job Done requires existing reconciliation blockers clear, settled supplier liability (including previously approved retained credit), confirmed payments and at least one current proof per payment/refund. It stores server actor/time/reason and a closure amount/document snapshot, and sets the existing finance check. Reopen requires a reason and records server audit, preserves money/files, invalidates the check. Closed remains closed after new Warehouse/financial evidence, displays review required, and surfaces an alert in Supplier Accounts. Financial edits, file deletion, Purchase PO changes and credit application to the closed target require reopening; acknowledgement and existing consumption of a verified source credit remain available. Existing bank execution, download delivery, journal retry and company/staff authorization remain unchanged.

Local Chrome candidate uses generated sample projections only, with no production business writes. Actual frontend Job Done -> Closed, Reopen -> Open, shortage disables Job Done and original file controls verified. Full suite567 tests:564 passed, same3 documented pre-existing failures (Master name authorization fixture, installment-status expectation, Sales/Buyer feedback language). Seven added backend/UI scenarios cover closure independent of customer invoice, all blocker classes, proof deletion, immutable closed membership, reopen reason, stale requests and lost-response idempotency.
